## 1\. Warehouse Manager Console

In this assignment, we are trying to build a Warehouse Manager. This assignment does **not** involve building a graphical interface, as that would require advanced graphics and UI programming. Instead, students will develop a **console-based warehouse simulation** in which a forklift operates within a grid-based warehouse, interacts with shelves, and manages items.  
The warehouse is represented as a **row–column grid**, with its dimensions and layout defined via **command-line arguments** (rows, columns, and a random seed). The random seed ensures that the warehouse layout is **deterministic and reproducible** across multiple runs.  
**Core Features**  
During a warehouse shift, the user can:

* Navigate the warehouse grid using directional commands (U, D, L, R).  
* Pause the shift at any time and return to the main menu.  
* Enter shelf locations to view items and pick exactly one item at a time.  
* Carry at most one item while moving through the warehouse.  
* Deliver a carried item only when standing on the START cell.  
* Resume a paused warehouse shift from the exact last forklift position.  
* View a detailed history table showing all actions performed during the shift.  
* Reset the warehouse to generate a new warehouse layout.  
* Abandon the current shift and exit the program.

## 2\. Classes or Entities in Warehouse

This section outlines the core domain entities of the Warehouse Manager system. These entities represent the elements displayed to and interacted with by the user in the console.

## 2.1 Warehouse Map

The warehouse map is a rectangular, grid-based layout shown in the console. Each map has a unique Warehouse ID that starts at 1\.  
The map is generated at runtime using the command-line arguments: rows, columns, and seed. Although the layout is generated randomly, using the same seed always produces the same warehouse map.  
Example (5 × 5 warehouse):  
\# \# \# \# \#   
\# F . S \#   
\# X X S \#   
\# S S X \# 

\# \# \# \# \#

## 2.2 Cells and Symbols

The **forklift** is displayed using the symbol **F** and temporarily replaces the symbol of the cell it occupies. When the forklift moves away, the original cell symbol (e.g., **O** or **.**) is restored.

* The START cell is always located at row \= 1, column \= 1\. It serves as:  
  * The point where the forklift begins each warehouse shift  
  * The **only location where items may be delivered**. Deliveries at any other location are not permitted.

* **Shelves** represent storage locations within the warehouse. Note the following things about the shelves.  
  * Each shelf initially contains one or more items (unless it is emptied later).  
  * Shelves may be visited multiple times.  
  * Items on a shelf can be viewed and picked up.  
  * Once all items are removed, the shelf remains empty but still exists (i.e., it is still represented with the letter S).  
  * When the forklift moves onto a shelf, a **Shelf Menu** is displayed automatically.

* **Items** are objects stored on shelves. Note that:  
  * Each item has a name (e.g., Toolkit, Printer, Box).  
  * Items exist either on a shelf or being carried by the forklift.  
  * Items cannot be dropped on the ground or placed back on shelves.  
  * Items are removed from the shelves after the forklift has picked it.

* The **forklift** represents the user in the warehouse. The forklift maintains:  
  * Its current position (row and column).  
  * Number of successful moves.  
  * Number of blocked movement attempts (hits).  
  * Whether it is currently carrying an item.  
  * Forklift cannot pick two items at a time.

## 2.3 Warehouse Session

A warehouse **shift** represents a single, continuous working **session**. A **shift** begins when the user selects “**Start warehouse shift”.** The shift can be paused using **Q** and resumed later. It ends automatically when all required work is completed.

## 2.4 Operation History

The system maintains a complete operation history of all actions performed across all shifts within a single program execution. This history can be viewed at any time from the main menu, persists across warehouse resets, and is never cleared during program execution.

## 3\. Warehouse Management Features

This section defines the system’s operational rules, session behaviour, history tracking, and lifecycle controls that govern how the warehouse simulation functions during execution.

## 3.1 Forklift Navigation Rules

This section defines the movement, interaction, and item-handling rules that govern the operation of the forklift within the warehouse.

* The forklift **cannot enter** wall cells (**\#**) or restricted cells (**X**).  
* When attempting to move into a blocked cell:  
  * Displays an error message,  
  * Increments the **hit counter**,  
  * Leaves the forklift in its current position.  
* Every **valid movement**:  
  * Moves the forklift to the target location,  
  * Increments the **move counter**.  
* The forklift may carry **at most one item** at a time.  
* Items **cannot be dropped**, stored on the ground, or returned to shelves.  
* Items are **removed** from the forklift **only when delivered at the START location**.

## 3.2 Session Management (Warehouse Shift)

This section describes what a **warehouse shift** is and how it starts, pauses, resumes, and completes during program execution.

* A warehouse shift represents a **single** session of work.  
* A shift:  
  * Starts when the user selects **Start warehouse shift**,  
  * Is paused when the user quits movement using **Q**,  
  * Can be resumed later from the main menu.  
* A shift **ends** automatically when:  
  * All shelves have been visited,  
  * All shelf items have been processed,  
  * The forklift is not carrying any item.  
* Upon completion, the warehouse map is **reset** (see Subsection 3.4), and control returns to the **main menu**.

## 3.3 Operation History

This section explains how user actions are recorded, stored, and made accessible across all warehouse shifts.

* The system maintains a detailed, persistent log of all actions, including:  
  * Warehouse ID,  
  * Operation type (e.g., move, hit, view shelf, pick item, deliver item),  
  * Item name (if applicable),  
  * Forklift position,  
  * Total moves and hits at the time of the action.  
* The operation history:  
  * Can be viewed at any time from the main menu,  
  * Persists across warehouse resets,  
  * Is never deleted during program execution. However, when the program quits, the operation history is lost.

## 3.4 Resetting and Exiting

This section outlines how the system resets the warehouse state, generates a new layout or terminates the program.  
**Reset Shift and Warehouse**

* Clears the current shift state,  
* Generates a new warehouse layout,  
* Increments the Warehouse ID,  
* Preserves the operation history.

**Abandon Shift and Exit**

* Gracefully terminates the program,  
* Displays a farewell message,

Do **not** use forced termination (e.g., System.exit()).

## 4.2 Initialising the Empty Warehouse Map

The warehouse map is a 2D grid whose size is defined by the **rows** and **columns** arguments.  
Before placing shelves or restricted areas, the map must be initialised as follows:

* Initialise a 2D array with rows and columns as the size of the array.  
* Each map has a warehouseID. Whenever the map is initialised or reinitialised, the warehouseID is incremented.  
* Set the boundary **Walls (\#)**, i.e., first row, last row, first column, last column of the 2D array.  
* Mark the **START cell** at row \= 1, column \= 1 with the symbol **O**,  
* Mark all remaining inner cells as **Aisles (.)** for now.

**Example: Empty 5 × 5 warehouse (before random shelf placement):**

## 4.3 Adding Shelves and Restricted Places to the Map

⚠️ **Important:** This process is **order-sensitive**. The steps below must be executed **exactly in the given order**. Failure to do so will result in incorrect initialisation and failed automated tests.  
**Step 1: Determine the number of shelves and restricted cells based on the seed.**  
A class named WarehouseGenerator has been provided to you in the scaffold. You must use the methods provided in this class to generate the number of shelves, the number of restricted places, the items on the shelves and the position of shelves/restricted places in the WarehouseMapclass.  
**Warning**: You must not make any changes to the WarehouseGenerator.java class.

* The number of shelves is generated using the *MIN\_SHELVES \= 1* and the number of aisle cells \+ 1  
* Calculate the remaining cells by subtracting the number of shelves generated from the number of aisle cells.  
* The number of restricted places is generated using the *MIN\_RESTRICTED=1* and the number of remaining cells \+ 1\. If the remaining cells are less than 2, then no restricted places are generated.

**Assumption:** The code for the above step is already provided to you in the scaffold in the file named WarehouseMap.java.  
**Step 2: Place Restricted Cells (X)**

* Iterate from 1 to the number of restricted places generated in Step 1\. Within the iteration, add the following steps.  
* Generate a row and column position to add a restricted place. Note that part of the code is provided to you in the scaffold. Modify the method findRandomEmptyCell in WarehouseMap.java to generate the position. However, the random position generator does not know if a position is already filled or open. You must only accept this row and column generated if the position in the map is marked as AISLE. If the place is already filled, let the while loop, present in the code, run to generate another row and column position randomly. Your task is to add this check to the code and then update the Map Cell with RESTRICTED type X.

**Step 3: Place Shelves (S)**

* Generate a row and column position as in Step 2\. Your task is the same as in Step 2\. Check if the position is AISLE, accept the row and column generated, otherwise discard and let the while loop run. Add the shelf to the position generated.  
* After the row and column positions are accepted, randomly generate a random number of items between 1 and 4 (both numbers inclusive).  
* Iterate from 1 to the number of items generated in the previous step and generate a random Item name to be put on the shelf. A method is already provided to you in the WarehouseGenerator class. You must invoke the method to generate a random item name. Once generated, add the item to the shelf.
