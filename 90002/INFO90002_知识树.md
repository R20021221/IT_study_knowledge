## A. SQL 语言

### A.1 DDL — 数据定义语言

```
DDL
├── CREATE
│   ├── CREATE TABLE                                    [SQL1 p7-8]
│   │   ├── 列定义：name + 数据类型 + 约束
│   │   ├── 约束：NOT NULL / AUTO_INCREMENT / PRIMARY KEY
│   │   └── 外键：FOREIGN KEY ... REFERENCES ...
│   │       ├── ON DELETE  RESTRICT|CASCADE|SET NULL    [SQL1 p11]
│   │       └── ON UPDATE  RESTRICT|CASCADE|SET NULL
│   ├── CREATE TABLE AS SELECT (CTAS)                   [SQL2 p31]
│   │   ├── 复制结构 + 数据
│   │   └── 复制结构（WHERE 1=0）
│   ├── CREATE VIEW                                     [SQL3 p15-18]
│   └── CREATE INDEX                                    [DBA p32]
│
├── ALTER                                               [SQL2 p30]
│   ├── ADD column
│   ├── DROP column
│   └── RENAME table
│
├── DROP                                                [SQL2 p31]
│   ├── DROP TABLE         (危险，无法 UNDO)
│   └── DROP VIEW
│
├── TRUNCATE TABLE                                      [SQL2 p31]
│   └── 等同 DELETE * FROM ... 但更快，不能 ROLLBACK
│
├── RENAME TABLE                                        [SQL2 p30]
│
└── 查看结构
    ├── DESCRIBE / DESC tablename                       [SQL1 p8]
    └── SHOW COLUMNS FROM tablename
```

### A.2 DML — 数据操作语言

```
DML
├── SELECT  ────────── 查询是 DML 的核心
│   ├── 完整骨架                                        [SQL1 p13]
│   │   SELECT [DISTINCT] expr
│   │   FROM table
│   │   [JOIN ... ON ...]
│   │   WHERE  row_condition
│   │   GROUP BY cols
│   │   HAVING group_condition
│   │   ORDER BY cols [ASC|DESC]
│   │   LIMIT n OFFSET m
│   │
│   ├── 投影 / 选择                                     [SQL1 p15-16]
│   │   ├── 投影 = SELECT 哪些列
│   │   └── 选择 = WHERE 哪些行
│   │
│   ├── 条件子句
│   │   ├── 比较：= < > <= >= != <>                     [SQL2 p6]
│   │   ├── 逻辑：AND / OR / NOT
│   │   ├── LIKE 模糊匹配                               [SQL1 p17]
│   │   │   ├── % 多字符
│   │   │   └── _ 单字符
│   │   ├── IN / NOT IN
│   │   ├── BETWEEN / NOT BETWEEN
│   │   └── IS NULL / IS NOT NULL
│   │
│   ├── 聚合函数                                        [SQL1 p18-19]
│   │   ├── COUNT(*)  vs  COUNT(col)         ← 易错点
│   │   ├── SUM / AVG / MIN / MAX
│   │   └── 都忽略 NULL（除 COUNT(*)）
│   │
│   ├── 分组与过滤                                      [SQL1 p20] [SQL2 p5]
│   │   ├── GROUP BY
│   │   └── HAVING（过滤组）vs  WHERE（过滤行）
│   │
│   ├── 排序与限制
│   │   ├── ORDER BY ... ASC|DESC                       [SQL1 p22]
│   │   └── LIMIT n  /  LIMIT n OFFSET m                [SQL1 p23]
│   │
│   ├── 别名                                            [SQL1 p21] [SQL1 p25]
│   │   ├── 列别名：col AS "name"
│   │   └── 表别名：tbl t
│   │
│   ├── 字符串函数                                      [SQL2 p7]
│   │   └── UPPER / LOWER / LEFT / RIGHT
│   │
│   └── 集合运算                                        [SQL2 p8-11]
│       ├── UNION / UNION ALL          (MySQL 支持)
│       ├── INTERSECT                  (MySQL 不支持)
│       └── EXCEPT / MINUS             (MySQL 不支持)
│
├── JOIN ────────── 连接
│   ├── 笛卡尔积 CROSS JOIN                              [SQL1 p26]
│   ├── INNER JOIN                                      [SQL1 p27]
│   ├── NATURAL JOIN                                    [SQL1 p28]
│   ├── LEFT OUTER JOIN                                 [SQL2 p16-17]
│   ├── RIGHT OUTER JOIN                                [SQL2 p18-19]
│   ├── FULL OUTER JOIN  (MySQL 不支持)                 [SQL2 p20]
│   ├── 反差查询 (LEFT JOIN ... WHERE B.id IS NULL)     [SQL2 p21-22]
│   └── 性能 / 可读性                                    [SQL2 p23-24]
│       ├── INNER > NATURAL
│       ├── UNION > JOIN
│       ├── JOIN > 子查询
│       ├── EXISTS（大集合）vs IN（小集合）
│       └── ON（连接）vs WHERE（过滤）
│
├── INSERT                                              [SQL1 p9] [SQL2 p25]
│   ├── 指定列：INSERT INTO t (cols) VALUES (...)
│   ├── 全列：INSERT INTO t VALUES (...)
│   ├── 多行：INSERT INTO t VALUES (...), (...), (...)
│   └── 来自查询：INSERT INTO t SELECT ...
│
├── UPDATE                                              [SQL2 p26-27]
│   ├── UPDATE t SET col=expr WHERE ...
│   └── CASE WHEN ... THEN ... ELSE ... END   ← 多分支
│
├── DELETE                                              [SQL2 p28]
│   ├── DELETE FROM t              ← 危险，全删
│   ├── DELETE FROM t WHERE ...    ← 安全
│   └── 受 ON DELETE 外键约束影响
│
├── REPLACE                                             [SQL2 p28]
│   └── 与 INSERT 相同；主键冲突时覆盖
│
└── 子查询                                              [SQL3 p4-13]
    ├── 标量子查询
    ├── 列表子查询：IN / NOT IN
    ├── 量化子查询：ANY / ALL
    └── 存在性子查询：EXISTS / NOT EXISTS
```

```
├── 用户管理

├── BACKUP TABLE / RESTORE TABLE

```

### A.4 写好查询的方法 `[SQL3 p22-24]`

```
1. 把数据库设计图当地图 — 找到所需字段所在的表
2. 把 SELECT 结构当模板
3. 一步步填空：
   ① 要哪些字段？  → SELECT
   ② 来自哪些表？  → FROM + JOIN
   ③ 过滤条件？    → WHERE
   ④ 是否分组聚合？→ GROUP BY / HAVING
   ⑤ 是否要排序？  → ORDER BY
```

### B.3 锁机制

```
Lock（锁）
├── 锁的粒度                                            [Trans p26-27]
│   ├── 数据库级 (SQLite, Access)
│   ├── 表级
│   ├── 页级
│   ├── 行级 (MySQL, Oracle 主流) ★
│   └── 字段级（很少用）
│
├── 锁的类型                                            [Trans p28-30]
│   ├── 二进制锁（lock/unlock）
│   ├── 共享锁 Shared / Read Lock
│   │   └── MySQL: SELECT ... FOR SHARE  /  LOCK TABLES ... READ
│   └── 排他锁 Exclusive / Write Lock
│       └── MySQL: SELECT ... FOR UPDATE  /  LOCK TABLES ... WRITE
│
├── 兼容性矩阵                                          [Trans p30]
│       ┌─────────┬────────┬──────────┐
│       │  持/请  │ Shared │ Exclusive│
│       ├─────────┼────────┼──────────┤
│       │ Shared  │   ✅   │    ❌    │
│       │ Exclu.  │   ❌   │    ❌    │
│       └─────────┴────────┴──────────┘
│
└── Strict 2PL（严格两阶段锁定） ★                      [Trans p35]
    ├── Phase 1 — Growing：只加锁，不放锁
    └── Phase 2 — Shrinking：事务结束时释放全部
```

### B.4 死锁

```
Deadlock                                                [Trans p31-34]
├── 成因
│   ├── 两事务互等对方解锁
│   ├── 或循环：T1→T2→T3→T1
│   └── 只发生在排他锁之间 ★
│
└── 应对
    ├── 超时（Timeout）
    ├── 预防（Prevention）— 按相同顺序加锁
    ├── 检测（Detection）— 选 victim 回滚
    └── 避免（Avoidance）— 算法判断
```

### C.2 DBMS 架构

```
DBMS Architecture                                        [DBA p9-17]
│
├── Storage Layer（存储层）
│   ├── File & Access Methods — 数据在内存与磁盘间移动
│   ├── Buffer Pool — 缓存表数据 + 索引数据
│   └── Disk Space Management
│
├── Query Processing（查询处理）                         [DBA p13]
│   ├── Parser/Compiler — 检查语法 + 权限
│   ├── Optimizer — 制定执行计划，最小化 cost
│   └── Executor — 保证 ACID
│
├── Concurrency Control（并发控制）                      [DBA p15]
│   ├── Transaction Manager
│   └── Lock Manager
│
└── Crash Recovery（崩溃恢复）                           [DBA p16]
    └── Log Manager
        ├── UNDO 信息（旧值，支持回滚 + 隔离）
        └── REDO 信息（变更，支持崩溃恢复）

【一次完整事务的 9 步流】                                [DBA p17]
1) 解析+权限+计划   2) 检查 Buffer Pool   3) 从磁盘读入
4) Transaction Mgr 确认数据就绪    5) Lock Mgr 加锁
6) 执行 SQL    7) 写 undo / 写 buffer / 写 redo
8) COMMIT     9) 写日志、释放锁，最终新数据写盘
```

### C.3 影响数据库性能的因素 `[DBA p18]`

```
性能优化方向
├── 缓存（Buffer Pool）
├── 数据文件在多盘上的分布
├── 高速可靠存储（SSD / RAID）
├── 数据库复制 + 服务器集群
├── 索引（加速查找与连接） ★
├── 选择合适的数据类型（尤其主键）
├── 避免长事务
├── 避免死锁
└── 优秀的查询执行计划
```

### C.4 索引

```
Index 索引                                               [DBA p20-32]
│
├── 为什么需要 ★                                        [DBA p20-22]
│   ├── 表扫描 O(n) 太慢（10万行 ≈ 5万次磁盘读）
│   └── 维持表本身有序代价高
│
├── 索引结构                                            [DBA p23-25]
│   ├── 内容：Key + RowLoc，按 Key 排序
│   ├── 查找：二分查找 O(log n)
│   └── 找到 Key 后跳到 RowLoc 拿整行
│
├── 索引的维护与代价                                    [DBA p26-29]
│   ├── PK 索引自动创建
│   ├── INSERT/UPDATE/DELETE 时必须更新索引
│   ├── 磁盘空间：小问题
│   └── 写入变慢：大问题 ← 不要建太多
│
├── 何时建 ★                                            [DBA p30]
│   ├── ✓ 频繁出现在 WHERE 的列
│   ├── ✓ JOIN 的列（PK / FK）
│   ├── ✓ 主键（自动）
│   ├── ✓ 外键（MySQL 自动）
│   ├── ✓ 唯一列（多数 DBMS 自动）
│   ├── ✗ 小表不要建
│   └── ✗ 命中率 > 15% 时索引未必有用
│
└── 优化器的判断                                        [DBA p31-32]
    ├── 多个索引可选时，DBMS 选 cost 最低的
    └── 表很小或选择性差时，可能直接全表扫描更快

【建索引语法】
CREATE INDEX index_name ON table(column);
```
